# V2.2 — Tool Registry Foundation

## Included

- Persistent API Tool Registry at `AgentWorkspace/.agent_state/tools.json`.
- CRUD endpoints for configurable HTTPS API tools; IDs, timestamps and versions are generated by the backend.
- New tools are disabled by default and require explicit enablement.
- Main Agent can receive enabled configured API tools during Tool Query turns.
- ToolManager supports asynchronous handlers for HTTP execution.
- Agent configuration stores `allowed_tools` references and validates them against registered API tool function names.
- Tool Management UI supports list, create, edit, enable/disable and delete.
- Agent Management displays registered API tools as Tool Permission checkboxes.

## Security boundary in this release

- Configurable API endpoints must use HTTPS, cannot contain embedded credentials, query strings or fragments, and must resolve to public IP addresses at configuration and execution time.
- Redirects are disabled; environment proxy inheritance is disabled; only GET and POST are supported; timeout is bounded; response size is limited to 1 MB.
- Credentials are referenced by uppercase environment-variable name only. Secret values are not written to the Tool Registry or returned by APIs. This release does not yet include a Keychain-backed Credentials UI.
- No package downloads, Git repository imports, shell commands, arbitrary Python execution, or Marketplace installation are implemented.
- DNS is resolved before the HTTP client connects; this is a useful SSRF mitigation but does not provide strict IP pinning against DNS rebinding. Treat configurable API endpoints as a restricted, owner-operated feature until a pinned-connection transport and stronger host allowlisting are implemented.

## Known integration limitation

`allowed_tools` is persisted and exposed in Agent Management, but Specialist Agent Runtime does not yet execute tools on behalf of Specialists. In this release, configured API Tools are exposed to Main Agent for Tool Query turns. Specialist-specific runtime permission enforcement and tool execution will be completed with the next orchestration stage.
